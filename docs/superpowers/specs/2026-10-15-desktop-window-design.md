# Portside 独立桌面窗口

本文记录 1.1.0 的单文件交付设计。1.1.1 默认便携目录的调整见[启动性能修正](2026-10-15-startup-performance-design.md)。

用户明确要求 Windows EXE，并补充“不是在浏览器打开”。本次将交互入口改为独立桌面窗口；保留已经实现的中文面板、端口与进程查询和确认结束操作。

采用 PySide6 的 QMainWindow + QWebEngineView。Qt 及渲染组件与 Python 一起打包，不依赖用户安装 Python 或 WebView2。用户双击后直接进入带标题栏、最小化、最大化和关闭按钮的应用；关闭窗口会停止采集与本机服务。界面仍通过仅监听回环地址的已有服务获取数据，继续校验会话令牌及来源。

对比备选方案：pywebview 更小但依赖 Windows WebView2；原生控件重写需要重新实现现有面板。内置 Qt 引擎体积较大，但能保持现有界面并提供独立可运行的交付。

同路径、同权限的 EXE 重复打开时，通过 Qt 本地 IPC 唤起已有窗口。实例锁按 EXE、权限和运行目录隔离；主实例持有互斥锁，异常退出后允许接管，避免依赖运行状态文件寻找面板。运行记录仅用于诊断和测试。

用户补充要求支持模糊搜索。普通查询采用不区分大小写的片段匹配，覆盖进程名、PID、端口和地址；如 `80` 能匹配 `8080`、`48080`。显式前缀 `:8080` 和 `pid:1234` 用于精确查找。内部服务在 Windows 使用独占端口绑定，首选端口被占用时自动使用空闲端口。

验收包括：单文件复制到中文路径并移除 PATH 中的 Python 后正常显示独立窗口；重复和同时启动复用窗口；最小化后重新打开可还原；关闭后端口与子进程退出，再次启动成功；真实 TCP/UDP 归属查询与测试进程结束；界面截图和既有回归测试。
