# 启动性能修正

用户反馈桌面应用启动较慢。保持已确认的 Windows EXE、独立窗口、模糊查询及进程操作设计，调整二进制交付方式。

## 测量与原因

原单文件 EXE 为 210,648,635 字节，归档解压后组件共 568,520,307 字节。本机连续两次测得：启动到子进程产生约 3.36 / 3.45 秒，窗口显示约 5.79 / 5.87 秒，实际数据界面就绪约 6.32 / 6.22 秒。绝大部分可以消除的额外等待出现在 Python 入口之前的解包阶段。

## 方案

默认使用 PyInstaller 目录模式，将 EXE 和 `_internal` 组件放在同一便携文件夹内，以 ZIP 分发。用户只解压一次，后续双击 EXE 直接运行。构建脚本提供 `-SingleFile` 可选参数，仍可生成原有单文件交付。

保留整个文件夹是快速版的使用要求，不能只复制其中的 EXE。目录模式消除重复解压，沿用 PyInstaller 标准加载和依赖定位流程。

## 启动动画

按用户追加要求，在构建 WebEngine 主窗口前先显示原生 Qt 启动画面：深色背景、应用图标、薄荷绿色旋转光环和流动进度条，配中文加载状态和取消按钮。原生动画无需新增依赖；仅在网页内加动画无法覆盖 WebEngine 初始化阶段，额外启动一个动画进程则会增加生命周期和打包负担。

启动画面先绘制，再在事件循环中初始化主窗口。页面加载完成即切换，不设置最短展示时间或伪造百分比。加载失败时仍显示主窗口和原有错误提示。取消启动、关闭主窗口、初始化异常均清理动画和窗口；重复启动激活当前可见窗口。Qt 控件全部在 GUI 线程创建，WebEngine 同步构造阶段可能短暂停顿，动画不承担性能提速承诺。

目录模式首次启动测得窗口约 2.6 秒出现，但有时数据界面在 5 秒后就绪。前端在初次快照尚未准备好时固定等待下一次两秒轮询；用确定性的虚拟时钟回归测试复现了该额外等待。初始未就绪时改为每 150ms 检查缓存，就绪后恢复两秒周期；暂停自动刷新、窗口隐藏或网络失败时不持续快速请求。

## 验证

新增可重复启动基准，测量窗口和实际数据界面就绪时间，使用隔离的实例目录和测试专用 Qt 调试端口。默认不强制硬件相关门槛，可显式指定本机目标；修正前的 4 秒界面就绪目标应失败，目录构建应通过。

独立验收支持复制整个便携包到中文路径，移除 Python 路径后验证界面、查询、进程结束、重复启动、关闭与重启。同时识别单文件的父子进程关系和目录模式的直接启动进程。

当前版本升级为 1.1.1，更新运行、开发和发布文档，并记录实测性能。通过验收后保留新版文件供用户直接打开。
