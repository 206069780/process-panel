# 启动优化设计

最终方案保留原有 HTML/CSS 界面、图表和交互，在独立 EXE 桌面窗口中运行。用户确认恢复原界面并保留启动优化。版本 1.1.2。

## 采集瓶颈

逐进程读取内存和 CPU 时，受限进程会让 psutil 回退到全机扫描。本机约 475 个进程的首次刷新约 1.7 秒，分析显示 278 次底层回退调用占约 1.6 秒。

Windows x64 改用一次 NtQuerySystemInformation 获取进程名称、创建时间、累计 CPU 和工作集。校验缓冲区、名称指针和记录步长；不支持时回退 psutil。身份仍采用 PID 加创建时间，CPU 差分按逻辑核归一化，网络连接及结束操作使用原有实现。

## 窗口加载

panel/window.py 只加载 QtCore/Network/Widgets 与原生启动画面，绘制后才导入 panel/web_window.py 和 WebEngine。创建 QApplication 前设置 AA_ShareOpenGLContexts。加载完成即切换主窗口，无固定动画展示时长。

保持导航来源限制、内存配置、禁用新窗口、确认结束、PID 创建时间校验和关键进程保护。退出时先销毁页面，再在 GUI 线程显式销毁窗口及其配置，避免后台 Python GC 释放 WebEngine 对象。

## 交付与验证

默认便携目录加 ZIP，可选单文件构建保持一致。分别测量动画、主窗口和实际数据可操作时间，不将动画出现当作秒开，不增加常驻或开机预加载。

验证真实采集身份、端口归属、CPU 差分/PID 重用/兼容回退、延迟导入、窗口生命周期、完整源码测试以及最终两种 EXE 的独立运行。记录三次实际 EXE 启动的中位数及首次运行波动，不承诺所有硬件严格小于一秒。
